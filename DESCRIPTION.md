# Personal Learning Quiz Bot

Покроковий порядок реалізації та release gates описані в [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md). Процес розробки через незалежних implementer/reviewer agents описаний у [WORKFLOW.md](WORKFLOW.md).

## Ідея

Personal Learning Quiz Bot — це персональний Telegram-бот для активного навчання, проходження тестів і відстеження прогресу.

Claude використовується як редактор навчального контенту: користувач передає йому книгу, PDF, конспект, статтю або транскрипт, а Claude аналізує матеріал, генерує набір запитань і через MCP зберігає його в системі бота.

Після цього Telegram-бот працює автономно: показує доступні набори, проводить тести, перевіряє відповіді, пояснює помилки та зберігає статистику. Для проходження вже створених тестів Claude API не потрібен.

Основна концепція продукту — персональний **knowledge gym**: Claude створює якісний навчальний контент, а Telegram забезпечує регулярну практику та вимірювання прогресу.

## Основний користувацький сценарій

1. Користувач додає книгу, PDF, текст, статтю або транскрипт у Claude.
2. Користувач просить Claude створити навчальний набір.
3. Claude аналізує матеріал і генерує структуровані запитання.
4. Claude викликає MCP-інструменти Quiz Bot і передає набір у систему.
5. Набір зберігається як чернетка.
6. Після завершення імпорту Claude публікує набір.
7. Користувач відкриває Telegram-бота, обирає набір і проходить тест.
8. Бот зберігає відповіді, помилки, результати та прогрес за темами.
9. Наступні сесії можуть автоматично включати слабкі теми та раніше допущені помилки.

Приклад запиту до Claude:

> Проаналізуй розділи 1–3 цієї книги. Створи набір із 25 запитань українською: 15 single-choice, 5 true/false і 5 ситуаційних. Додай пояснення правильної відповіді, рівень складності, тему та посилання на відповідний розділ. Передай набір у мій Quiz Bot.

## Загальна архітектура

```text
Книга / PDF / стаття / конспект / транскрипт
                         |
                         v
                      Claude
               аналізує матеріал
                         |
                         v
               Quiz Bot MCP server
                         |
                         v
                    SQLite база
                         ^
                         |
                   Telegram-бот
                         |
                         v
        тести -> пояснення -> статистика
```

Система складається з трьох основних частин:

- **Telegram Bot** — інтерфейс проходження тестів і перегляду результатів.
- **Quiz application/core** — бізнес-логіка наборів, запитань, спроб, оцінювання та повторення.
- **MCP server** — інтерфейс, через який Claude створює та редагує навчальний контент.

Telegram-бот і MCP-сервер повинні використовувати одну application layer і одну базу даних. MCP не має напряму записувати довільні дані в SQLite в обхід валідації.

## Варіанти запуску MCP

### Локальний варіант

Найкращий варіант для першої персональної версії:

```text
Claude Desktop / Claude Code
             |
             v
      локальний stdio MCP
             |
             v
    Quiz application + SQLite
             ^
             |
       Telegram long polling
```

Переваги:

- не потрібен окремий Claude API key;
- можна використовувати Claude через особисту підписку;
- MCP, бот і база працюють на одному комп'ютері;
- не потрібно публікувати MCP endpoint в інтернеті;
- мінімальна вартість і проста інфраструктура.

Обмеження:

- комп'ютер має бути увімкнений, щоб Telegram-бот працював;
- створення наборів через MCP доступне лише з налаштованого локального Claude;
- необхідно безпечно зберігати локальні credentials і Telegram token.

### Віддалений варіант

У майбутньому бот, база і MCP можуть працювати на сервері:

```text
Claude Web / Desktop / Mobile
             |
             v
      remote MCP over HTTPS
             |
             v
    Quiz application + database
             ^
             |
         Telegram Bot
```

Віддалений MCP повинен мати автентифікацію, HTTPS, обмеження доступу і захист від неавторизованого створення або зміни наборів.

## MCP-інструменти

Для першої версії достатньо таких інструментів:

### `quiz.create_set`

Створює порожній набір у статусі `draft` і повертає його стабільний ID.

Основні параметри:

- назва;
- опис;
- мова;
- джерело;
- список тегів;
- назва книги або матеріалу;
- використані розділи.

### `quiz.add_questions`

Додає до набору одну пачку запитань. Питання потрібно передавати невеликими batches, наприклад по 10–20, замість одного величезного MCP-виклику.

### `quiz.update_set`

Оновлює метадані набору або окремі запитання до публікації.

### `quiz.get_set`

Повертає набір для перевірки Claude перед публікацією.

### `quiz.list_sets`

Показує доступні чернетки й опубліковані набори.

### `quiz.publish_set`

Перевіряє набір і переводить його зі статусу `draft` у `published`. До публікації набір не показується в Telegram-боті.

### `quiz.archive_set`

Приховує набір, але не видаляє його результати та історію проходжень.

Рекомендований процес імпорту:

```text
quiz.create_set
        |
        v
quiz.add_questions (batch 1)
        |
        v
quiz.add_questions (batch 2)
        |
        v
quiz.get_set / validation
        |
        v
quiz.publish_set
```

Цей процес не дозволяє користувачу побачити частково створений або пошкоджений набір.

## Структура навчального набору

Приклад структури питання:

```json
{
  "type": "single_choice",
  "question": "Яка головна мета реплікації?",
  "options": [
    "Зменшити розмір бази",
    "Підвищити доступність",
    "Замінити індекси",
    "Уникнути транзакцій"
  ],
  "correctOption": 1,
  "explanation": "Реплікація дозволяє зберігати копії даних на кількох вузлах.",
  "sourceReference": "Розділ 2",
  "difficulty": "medium",
  "topic": "replication"
}
```

Кожне питання бажано зберігати з такими полями:

- тип питання;
- текст питання;
- варіанти відповіді;
- правильна відповідь;
- пояснення;
- посилання на джерело або розділ;
- тема;
- складність;
- додаткова підказка;
- порядок у наборі.

## Типи запитань

Для MVP:

- `single_choice` — одна правильна відповідь;
- `multiple_choice` — декілька правильних відповідей;
- `true_false` — твердження, яке потрібно підтвердити або спростувати.

Для наступних версій:

- `short_answer` — коротка текстова відповідь;
- `open_answer` — розгорнута відповідь;
- `scenario` — ситуаційна задача;
- `code` — питання з фрагментом коду;
- `ordering` — встановлення правильної послідовності;
- `matching` — зіставлення термінів і визначень.

Перші три типи перевіряються звичайним кодом і не потребують AI API під час проходження. Для оцінювання вільних відповідей у майбутньому може знадобитися Claude, OpenAI, Gemini або локальна модель.

## Інтерфейс Telegram-бота

Головне меню:

- 📚 Мої набори
- ▶️ Продовжити навчання
- 🔁 Повторити помилки
- 🧠 Слабкі теми
- 📊 Статистика
- ⚙️ Налаштування

Під час тесту бот показує:

- поточне питання;
- номер питання та загальну кількість;
- inline-кнопки з варіантами;
- прогрес проходження;
- можливість завершити або призупинити тест.

Після відповіді бот показує:

- чи правильна відповідь;
- правильний варіант;
- коротке пояснення;
- посилання на розділ джерела;
- кнопки `Наступне`, `Повторити пізніше` та, за наявності, `Показати підказку`.

Приклад фінального результату:

```text
Результат: 17/20 — 85%

Сильні теми:
- Replication — 100%
- Data models — 90%

Потрібно повторити:
- Transactions — 50%
- Serializability — 40%
```

## Статистика

Система має зберігати:

- кількість проходжень;
- загальний результат кожної спроби;
- відповіді на кожне питання;
- час проходження;
- точність за наборами;
- точність за темами;
- складні та слабкі питання;
- серію навчальних днів;
- дати останньої та наступної практики.

Корисні представлення статистики:

- результат останньої спроби;
- прогрес між першою та останньою спробами;
- найсильніші та найслабші теми;
- історія неправильних відповідей;
- кількість питань, які потрібно повторити;
- умовний рівень засвоєння набору.

## Адаптивне навчання і spaced repetition

Наступні навчальні сесії можуть формуватися на основі історії відповідей:

```text
неправильно -> повторити завтра
важко       -> повторити через 3 дні
правильно   -> повторити через 7 днів
дуже легко  -> повторити через 21 день
```

На початку можна використати просту rule-based модель. У майбутньому її можна замінити на алгоритм на кшталт SM-2 або FSRS.

Адаптивна сесія може включати:

- питання, на які користувач відповів неправильно;
- питання зі слабких тем;
- питання, строк повторення яких уже настав;
- невелику кількість нових питань;
- контрольні питання, які давно не повторювалися.

## Валідація AI-контенту

Claude генерує контент, але application layer повинна перевіряти його перед збереженням і публікацією.

Мінімальні правила:

- питання не може бути порожнім;
- `single_choice` має містити щонайменше два варіанти;
- індекс правильної відповіді має існувати;
- `multiple_choice` має містити хоча б одну правильну відповідь;
- пояснення та посилання на джерело бажані для кожного питання;
- складність має бути одним із дозволених значень;
- набір без питань не можна опублікувати;
- дублікати запитань потрібно виявляти до публікації.

Навіть структурно правильна AI-відповідь може містити фактичну помилку. Тому MCP flow повинен дозволяти Claude або користувачу переглянути набір перед публікацією.

## Безпека

Оскільки бот персональний, потрібно додати `ALLOWED_TELEGRAM_USER_ID` і відхиляти всі повідомлення від інших користувачів.

Також необхідно:

- не зберігати Telegram token у репозиторії;
- не зберігати MCP credentials у Git;
- вимагати автентифікацію для remote MCP;
- валідувати кожний MCP-виклик;
- обмежити максимальну кількість запитань у batch і наборі;
- використовувати стабільні UUID для наборів, питань і спроб;
- архівувати дані замість безповоротного видалення;
- обмежити MCP write tools лише операціями з навчальним контентом.

## MVP

Перша корисна версія має включати:

1. SQLite persistence.
2. Персональний Telegram allowlist.
3. Створення наборів через MCP.
4. Статуси `draft`, `published`, `archived`.
5. Batch-імпорт запитань.
6. Типи `single_choice`, `multiple_choice`, `true_false`.
7. Перегляд доступних наборів у Telegram.
8. Проходження повного тесту.
9. Локальну перевірку відповідей.
10. Пояснення після відповіді.
11. Збереження спроб і результатів.
12. Повторення неправильних відповідей.
13. Базову статистику за наборами та темами.

MVP не потребує:

- AI API всередині Telegram-бота;
- оцінювання відкритих відповідей;
- складного web UI;
- автоматичного витягування платного контенту з Udemy або Coursera;
- багатокористувацьких ролей;
- складної recommendation model.

## Наступні етапи

Після MVP можна додати:

- щоденний мікроквіз із 5–10 запитань;
- spaced repetition;
- адаптивні сесії зі слабких тем;
- flashcards з помилок;
- режим екзамену без миттєвих підказок;
- режим співбесіди без варіантів відповіді;
- генерацію практичних і ситуаційних задач;
- оцінювання коротких і відкритих відповідей через AI API;
- голосові відповіді в Telegram;
- імпорт зі статей, відео, курсів і транскриптів;
- link-first імпорт матеріалів;
- можливість поділитися набором за кодом або посиланням;
- web dashboard зі складнішою аналітикою;
- автоматичну генерацію додаткових пояснень і прикладів.

## Подальший напрям продукту

Продукт не повинен перетворюватися на загальний AI-чат. Його основна цінність — перетворення реального навчального матеріалу на регулярну практику з вимірюваним прогресом.

Пріоритети розвитку:

1. Мінімальне тертя під час імпорту матеріалу.
2. Якісні питання з прив'язкою до джерела.
3. Швидке проходження в Telegram.
4. Корисні пояснення після помилок.
5. Повторення у правильний момент.
6. Зрозуміла статистика засвоєння тем.
